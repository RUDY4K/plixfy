## 3 · API ground-truth checks (live evidence)

### GameMonetize iframe gating — **the critical finding**

Test command (Bash):
```bash
curl -sSI \
  -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/121.0.0.0 Safari/537.36" \
  -H "Accept: text/html,application/xhtml+xml,..." \
  -H "Accept-Language: en-US,en;q=0.9,ar;q=0.8" \
  -H "Sec-Fetch-Mode: navigate" \
  -H "Sec-Fetch-Site: cross-site" \
  -H "Sec-Fetch-Dest: iframe" \
  -H "Referer: https://plixfy.com/games/moving-magnet" \
  "https://html5.gamemonetize.co/7pmla0dtaz56alpxp7bnit4fvh3y2y9a/"
```

Response (verbatim):
```
HTTP/1.1 403 Forbidden
Date: Sun, 24 May 2026 09:38:18 GMT
Content-Type: text/html; charset=UTF-8
Server: cloudflare
cf-cache-status: DYNAMIC
CF-RAY: a00b53a24f296cdd-DMM
```

**Interpretation:** GameMonetize uses Cloudflare WAF to block iframe requests from non-allowlisted origins. The block fires even with full realistic Chrome 121 headers and a plixfy referer. This means **GameMonetize cannot be used as a public drop-in CDN; the publisher domain must be registered in their dashboard before games render at all.**

### GameDistribution iframe — contrast

Same headers, against `https://html5.gamedistribution.com/2e44fb60fd3f4606b1b06c17a2b9d60d/`:
```
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Server: nginx/1.27.3
Access-Control-Allow-Origin: *
```

**Interpretation:** GD does not block at the network layer. But — per the user's prior session — the *content* of the page shows a "CLICK HERE TO PLAY" interstitial or redirects when the requesting domain is not allowlisted in GD's dashboard. So GD blocks at the application layer, GameMonetize blocks at the network layer.

## 7 · Open questions — verify before going to production

Things `research_report.md` recommends that should be confirmed by signing up and getting it in writing:

1. **Playgama actual contract revenue share.** Public wiki says 70–90% tiered, partner landing page says "up to 50%." Get the partner agreement and the tier definition (does "earnings" mean monthly, all-time, or per-game?) explicit before integrating.
2. **Playgama Saudi-recipient crypto payout.** They say "on request" — open a ticket pre-integration to confirm USDT/USDC to a specific Saudi-friendly wallet works.
3. **GameMonetize allowlisting cost / latency.** Open a support ticket asking if `plixfy.com` can be pre-allowlisted in their CDN before integration, what their SLA on the allowlist update is, and whether the allowlist propagates to Cloudflare in real-time.
4. **GameDistribution publisher revenue share (vs. the 33% developer rate).** Log into the publisher dashboard and confirm — the public terms page only documents the developer side.
5. **Famobi 50K-MAU re-entry criteria.** Confirm that the 50K floor is total visits (Cloudflare/GA-measured) or unique users — make sure your traffic-measurement methodology matches theirs when you cross the threshold.

---

**Bottom line:** The recommendations in `research_report.md` are evidence-backed but not contract-backed. Use this document to drive the next-step conversations with each platform's sales/support team. Where you spot a contradiction, trust the live API probe over the marketing page every time.
