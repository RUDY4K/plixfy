# التشغيل setup-001

- الحالة: complete
- التاريخ: 2026-08-26
- الهدف: تأسيس واختبار بنية مدير Plixfy والوكلاء الديناميكيين.
- النطاق: ملفات `ops/agent-team` وتعليمات المشروع وفاحص البنية فقط.
- خارج النطاق: كود الموقع، الإنتاج، النشر، الحسابات والأسرار.
- base branch: `main`

## الموجة الأولى

- مراجع البنية: اكتملت؛ طلب تحقق أعمق وذاكرة تشغيل مستقلة.
- مراجع الأمن: اكتملت؛ منع وكلاء الكتابة حتى يطبق العزل والموافقة.
- مراجع تغطية الأدوار: اكتملت؛ اعتمد الأدوار الأساسية كبوابات routing.

## التحقق

- `npm run agents:check`: نجح قبل التحسينات.
- إعادة الفحص بعد التحسينات: نجحت مع تحذيرات مقصودة عن حدود العزل التقني.

## قرارات الأمان

- الوضع الافتراضي قراءة فقط.
- لا وصول للأسرار للوكلاء المتخصصين.
- لا نشر أو إجراء خارجي دون موافقة المالك المسجلة.
- التشغيل التجريبي المسموح الآن قراءة فقط ومراقب، مع شبكة مقيدة وأسرار محجوبة.
- ملفات السياسة لا تحول مساحة كاملة الصلاحيات إلى sandbox؛ مسؤولية الإنفاذ على
  المشغّل، ويمنع تشغيل وكيل كتابة عند غياب العزل.

## اختبار القبول النهائي

- السيناريو: إطلاق لعبة أصلية مع حملة نمو وتحقيق دخل، دون تنفيذ فعلي.
- قرار المدير: 47 وكيلًا دقيقًا في 6 موجات، نتج العدد من تفكيك المسؤوليات ولم
  يكن هدفًا أو سقفًا مسبقًا.
- غطت الموجات الاكتشاف، تصميم اللعبة، التنفيذ، الحملة، المراجعات المتخصصة، ثم
  `qa-compliance` وبوابة موافقة المالك.
- النتيجة: العدد الديناميكي والتبعيات وملكية الملفات وبوابات الموافقة واضحة.
- أضيف لاحقًا مشغّل قراءة تقني يستخدم snapshot دقيقًا وWSL2/bubblewrap ونموذجًا
  بلا أدوات، مع اختبارات رفض للأسرار والعبور والكتابة والشبكة.
- أضيف v2.0 للكتابة المعزولة: عمليات `create`/`replace` منظمة داخل worktree
  مؤقت مستقل لكل وكيل، وتسليم patch للمراجعة دون دمج. النشر يبقى مغلقًا.
- نجحت مجموعة اختبارات العزل والاختبارات العدائية كاملة، وتشمل NTFS 8.3
  وhardlinks وTOCTOU وحقن إعدادات Git وcheckout filters، وفحص سياق المدير،
  وإيصالات فشل التخطيط والتحقق المسبق، ومصدر الأدلة وQA وstdin كبيرًا ومحاكي
  Claude ومحاكي Codex يتحققان من no-tools ومن بيئة تشغيل منقحة.
- اختبار الفشل المتزامن يثبت حفظ نتائج الوكلاء الناجحين وإصدار receipt نهائي
  `failed` يتضمن النموذج وعدد الاستدعاءات والمهام الفاشلة والمعلقة.
- النجاح التقني لا يتحول إلى قبول دلالي تلقائي؛ تحفظ النتيجة كـ`modelVerdict`
  ويكون قرار المضيف `review_required` حتى مراجعة المالك.
- اختبارات وسيط الكتابة تغطي تداخل الملكية، dirty targets، base drift، traversal،
  أسرار المحتوى، روابط Windows، التعديلات خارج الوسيط، والتحقق من patch دون
  تغيير checkout الرئيسي.
- التشغيل الحقيقي محصور في CLI، مع consent قصير العمر أحادي الاستخدام؛ والأدلة
  مرتبطة ببصمة المصدر ونطاق الأسطر والنص المطابق أو ببصمة نتيجة التبعية.
