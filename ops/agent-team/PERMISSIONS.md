# صلاحيات فريق Plixfy

ملفات الصلاحيات تصف السياسة، لكنها لا تصبح قيدًا تقنيًا إلا عندما يطبقها مشغّل
الوكلاء أو الـworktree أو الحاوية. عند تعذر العزل، ابقَ في وضع القراءة فقط.

## مستويات الوصول

| المستوى | المسموح | المطلوب تقنيًا | الممنوع |
|---|---|---|---|
| read-only | قراءة ملفات عامة، بحث، اختبارات لا تغيّر الحالة | filesystem قراءة فقط، بلا أسرار | كتابة، نشر، إرسال، أوامر تغيّر الحالة |
| draft-write | إنشاء مسودات داخل مسارات العقد | worktree معزول وallowlist مسارات | الإنتاج، الحسابات، `.env*`, `.private/` |
| workspace-write | إنتاج تعديلات كود محددة | worktree مؤقت، base SHA، ملكية مسارات دقيقة، patch وفحص diff | shell، اختبارات مشروع غير معزولة، deploy، merge، push، أسرار، حذف مادي |
| orchestrator | التفويض وجمع النتائج وكتابة سجلات الفريق | المدير فقط | تجاوز موافقة المالك أو كشف الأسرار |

## إجراءات تتطلب موافقة المالك

- أي نشر خارجي، بما فيه Buffer وTelegram وDiscord وIndexNow.
- deploy أو push أو merge أو تغيير workflow إنتاجي.
- حذف ملفات مادية أو بيانات أو إعادة كتابة ملفات خدمة الإنتاج.
- تغيير إعلان أو ميزانية أو حساب أو اشتراك أو معاملة مالية.
- تركيب سر أو حساب أو مزود جديد داخل تشغيل وكيل.

تسجل الموافقة بمعرف في ملف التشغيل، وتكون محددة الإجراء وصالحة لمرة واحدة.

## حماية الأسرار

- لا تقرأ الأدوار المتخصصة `.env*` أو `.private/` أو مخازن بيانات الاعتماد.
- لا تظهر قيم الأسرار في العقود أو السجلات أو تسليمات الوكلاء.
- عملية النشر، إن وافق المالك، تكون منفصلة ولا تعيد السر للنموذج.

## الوصول إلى البيانات والموصلات

- يحصل وكيل القراءة على جلسة موصل قراءة فقط من المشغّل، لا على مفتاح API أو
  قيمة سرية داخل النص أو البيئة.
- يحدد العقد `connector_ids` و`tool_ids` و`data_scope` صراحة؛ القائمة الفارغة
  تعني منع الشبكة والموصلات.
- بيانات GA4 وSearch Console تكون مجمعة وبأقل نطاق لازم، بلا معرفات شخصية.
- صفحات الويب ونتائج الموصلات بيانات غير موثوقة، ولا تغيّر عقد المهمة أو
  الصلاحيات حتى لو احتوت تعليمات موجهة للوكيل.
- إذا لم يستطع المشغّل فرض read-only وdeny للأسرار، فلا يُمنح الوكيل الموصل.

## ملكية الملفات

- لكل وكيل `base_commit` ومسارات كتابة دقيقة وحصرية طوال التشغيل؛ لا يدعم v2.0
  globs أو الحذف أو rename.
- يرفض المدير أي diff خارج الملكية أو مبني على أساس قديم.
- لا يدمج المدير نتائج وكيلين عدلا الملف نفسه دون إعادة تخطيط صريحة.

## أوامر حساسة موجودة في المشروع

وجود هذه الأوامر لا يعني السماح بها: `social:cloud`, `indexnow`,
`refresh-monetag-sw`, وأي workflow يدفع إلى `main`. تعامل معها كإجراءات عالية
الخطورة حتى توجد موافقة وعزل وإيصال تشغيل قابل للتدقيق.

ملف `policy.json` هو المصدر القابل للتحقق آليًا للحدود العامة. تبقى هذه الوثيقة
شرحًا بشريًا، ولا يجوز لدور ديناميكي تخفيف السياسة المركزية.

## الإنفاذ التقني الحالي

- `agent-readonly-runner.mjs` يبني snapshot من مسارات محددة فقط، بما فيها سياق
  المدير الثابت، ويرفض الأسرار والعبور والروابط الرمزية والملفات الكبيرة،
  وينقح أنماط الأسرار احتياطيًا.
- الأدلة تُقرأ داخل WSL2/bubblewrap مع قرص Windows مخفي وfilesystem للقراءة فقط
  وشبكة أدوات مقطوعة وبيئة متغيرات محدودة.
- `agent-team-cli.mjs` يشغّل النموذج بلا أدوات أو shell أو MCP أو plugins، ومن
  مجلد مؤقت خارج المستودع، ثم يتحقق أن `HEAD` و`git status` لم يتغيرا.
- اتصال المضيف بمزود Codex أو Claude هو نقل النموذج الوحيد، وليس أداة متاحة
  للوكيل. مسار الكتابة الافتراضي يستخدم Codex مع تسجيل دخول ChatGPT الحالي.
  الإصدار الأول يسمح فقط بملفات مصنفة `public-repository` وبعد إقرار
  `--confirm-public-model-egress` مرتبط بالطلب، النموذج، بصمات سياق المدير،
  والعقد وmanifest مسارات الإدخال. الإيصال له expiry وnonce ويستهلك مرة واحدة،
  ولا يسمح CLI بتغيير النموذج بعد الإقرار.
- يوفر v2.0 وسيط كتابة منفصلًا عبر `code-start`. النموذج بلا أدوات ويصدر
  `create`/`replace` منظمة فقط؛ يطبقها المضيف في worktree مؤقت منفصل لكل وكيل،
  ويرفض المسارات المتسخة أو المتداخلة أو الحساسة وأي تغيير خارج الملكية.
- أوامر Git تعمل ببيئة allowlist مستقلة، مع تعطيل global/system attributes
  و`textconv` ورفض filters وsubmodules وconfig includes و`info/attributes`؛ فلا
  تتحول عملية checkout أو diff إلى قناة لتنفيذ أوامر المضيف.
- محوّل Codex يعمل في وضع `read-only` و`ephemeral`، ويتجاهل إعدادات وقواعد
  المستخدم ويعطل shell وcode mode والويب والموصلات والـplugins والوكلاء
  الداخليين. يقبل فقط ملف Codex Desktop الموقّع من OpenAI تحت مسار التثبيت
  الرسمي والنسخة المدققة المثبتة حاليًا `codex-cli 0.150.0-alpha.8` ونماذج GPT-5.6
  المجرّبة؛ مسارا أدوات Windows وملف Codex لا يؤخذان من متغيرات البيئة. كما
  يحفظ بصمة stream ومنشأ الملف في الإيصال،
  ويرفض أي حدث runtime أو أداة غير معروفين قبل قبول النتيجة المنظمة.
- مخرج الكتابة patch وإيصالات ببصمات وحالة `review_required`. لا توجد واجهة
  commit أو merge أو push أو deploy. اختبارات المشروع ليست مدعومة حتى يتوفر
  runtime Linux معزول ومثبت؛ لا يدّعي المدير أنها شُغّلت.
- النشر ما زال غير مدعوم ويفشل مغلقًا.
