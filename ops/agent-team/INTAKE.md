# استقبال مهام فريق Plixfy

يملأ المدير الحد الأدنى اللازم قبل اختيار عدد الوكلاء. لا يؤخر العمل بسبب حقل
غير مؤثر؛ يسجل الافتراض بوضوح ويخفض درجة الثقة إن كانت البيانات ناقصة.

## حقول عامة

- الهدف والنتيجة القابلة للقياس.
- النطاق وخارج النطاق.
- وضع التنفيذ: قراءة فقط، مسودة، أو تعديل معزول.
- هل يمنع المستخدم أي كتابة داخل المستودع؟
- الموعد والميزانية التي اعتمدها المالك، إن وجدت.
- مصادر البيانات المسموحة ومعرفات الموصلات ونطاقها.
- القيود والمخاطر والإجراءات التي تحتاج موافقة.

## انخفاض الزيارات

- `metric`: sessions أو users أو clicks أو impressions أو conversions.
- `decline_start`: أول تاريخ ظهر فيه الانخفاض.
- `timezone`: المنطقة الزمنية المستخدمة في التقارير.
- `comparison_windows`: فترة المشكلة وفترة الأساس مع مراعاة الموسمية.
- `segments`: البلد، اللغة، الجهاز، القناة، الصفحة المقصودة، ونوع البحث.
- `known_releases`: النشرات، تغييرات المحتوى، القياس، البنية، أو الحملات.
- `data_sources`: GA4 وSearch Console والسجلات والمراقبة المتاحة.
- `data_definition`: تعريف موحد لما يدخل في المقياس وما يستبعد منه.

بعد الاستقبال يفكك المدير التشخيص إلى وكلاء ضيقين حسب `ROUTING.md`. لا يوجد
عدد ثابت؛ يزداد العدد عندما توجد فرضيات أو مصادر بيانات مستقلة تستحق الفصل.
